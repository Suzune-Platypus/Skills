# F6：テスト

## このフェーズの目的

F1〜F5で設計・確定した仕様に対して、実装が正しく動作するかを確認する。
🤖（自動確認）と👁（手動確認）を組み合わせて、品質を担保する。

> 🤖 = ツール・AIで自動確認できる項目
> 👁 = 人間が目視・操作で確認する必要がある項目

---

## 進め方

以下の順序で進める。テストケースを先に作ってから振り分けるのが効率的。

```
1. テスト方針を決める（範囲・対象外の明確化）
2. テストケースを作成する（対象・対象外を含めて全て列挙）
3. テストケースを🤖/👁に振り分ける
4. Codeによるソースレベル検証を依頼する
5. 🤖自動確認を実行する
6. 👁手動確認を実行する
```

---

## 6-1. テスト方針

| 確認項目 | 補足 |
|---------|------|
| テスト範囲を決めたか | 全機能をテストするか、重要機能に絞るかを決める |
| テスト対象外の機能を明確にしたか | 対象外としたものはテストケース内に「対象外」として明示する。なんとなく省かない |

**対話のコツ：** 「どこまでテストしますか？」と聞いて、スコープに応じた範囲を一緒に決める。
対象外にする場合は「なぜ対象外にするか」の理由も一言記録しておく。

---

## 6-2. テストケースの作成

> 方針が決まったら、🤖/👁への振り分けより先にテストケースを全て作成する。
> F2の操作シナリオ・F4のバリデーションルールを参照しながら作成する。

以下の形式でテストケース一覧を作成する。対象外の機能も「対象外」として明示する。

```
## テストケース一覧

| No | テスト対象 | 操作手順 | 期待結果 | 🤖/👁 | 備考 |
|----|----------|---------|---------|------|------|
| 1  | 新規登録 | フォームに入力して保存ボタンを押す | 一覧に追加される | 👁 | |
| 2  | バリデーション | 必須項目を空のまま保存ボタンを押す | エラーメッセージが表示される | 🤖 | |
| 3  | ○○機能 | - | - | 対象外 | 今回のスコープ外のため |
| ...| ...      | ...     | ...     | ... | |
```

テストケースが出揃ったら🤖/👁の振り分けを行う。

---

## 6-3. ソースレベル検証（Codeへの依頼）

> テスト実行の前に、Claude Codeに仕様書とソースコードの整合確認を依頼する。
> 「動かして確認する」前に「読んで確認する」ステップを入れることで、
> 実行時に見つけにくいバグや仕様との乖離を事前に発見できる。

**Codeへの依頼内容：**
- 仕様書（設計書・データ設計書等）とソースコードを照合して、乖離がないか確認する
- バリデーションルールが実装に正しく反映されているか確認する
- 命名規則・コーディング規約（F5-3）が守られているか確認する
- 明らかなバグ・未実装箇所があれば報告する

---

## 6-4. 🤖 自動確認

> ツール・AIが確認できる項目。Claude Codeと連携してテストを実行する。

| 確認項目 | 補足 |
|---------|------|
| ビルドが通るか | エラーなくビルドできるかを確認する |
| コンソールエラーが出ていないか | ブラウザのコンソールにエラー・警告が出ていないか |
| バリデーションが仕様通りに機能するか | F4で決めたバリデーションルールが正しく動くか |
| CSVインポート・エクスポートが正しく動くか | F4で決めたフォーマット仕様通りに動くか（該当する場合のみ） |

---

## 6-5. 👁 手動確認（操作シナリオ）

> 人間が実際に操作して確認する項目。F2の操作シナリオと照合しながら進める。

| 確認項目 | 補足 |
|---------|------|
| CRUD全操作が画面から正しく動くか | Create・Read・Update・Deleteを一通り操作して確認する |
| 画面フローが仕様通りか | 戻る・キャンセル・保存後の遷移先が設計通りか |
| 確認ダイアログが必要な箇所で表示されるか | F2で「要」と決めた箇所で正しく表示されるか |
| 空の状態・エラー状態の表示が意図通りか | データ0件・通信エラー時の表示が仕様通りか |
| レスポンシブ表示が崩れていないか | F2で決めたレスポンシブ方針通りにモバイル・PCで表示されるか |
| 意図した通りの見た目・トンマナになっているか | F2-0で決めた画面共通仕様と照合する |

---

## 6-6. 👁 データ確認

> データの整合性を人間が目視で確認する。

| 確認項目 | 補足 |
|---------|------|
| 保存したデータが正しく表示されるか | 入力した内容が一覧・詳細画面に正しく反映されるか |
| 削除後にデータが残っていないか | 物理削除の場合はDBからも消えているか確認する |
| インポートしたデータが正しく反映されるか | CSVインポートがある場合のみ |

---

## F6完了の確認

以下が揃っていればF6完了とする：

- [ ] テスト範囲と対象外が明確になっているか
- [ ] テストケース一覧が作成されているか（対象外も含めて明示）

- [ ] 🤖自動確認が完了しているか
