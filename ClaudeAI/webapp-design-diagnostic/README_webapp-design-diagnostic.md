# webapp-design-diagnostic Skill README

**Webアプリの設計をClaudeと進めながら、あなたの設計スキルを診断するSkillです。**  
要件整理から画面設計・技術スタック・データ設計・テストまで、F1〜F6のフェーズに沿って設計書を作成しながら、7軸のレーダーチャートでスキルを可視化します。

---

## 1. このSkillでできること

- **F1〜F6の設計フェーズを対話形式で進める**（要件整理・画面設計・アーキテクチャ・データ設計・実装前確認・テスト）
- **設計書をテンプレート形式で作成する**（md / docx）
- **既存の仕様書をテンプレートと照合して不足を分析する**
- **設計スキルを7軸のレーダーチャートで診断する**（診断モードオン時）
- **「AIとうまく対話できているか」をAIコラボ深度として評価する**

---

## 2. こんな人におすすめ

- **自分の設計スキルがどのくらいか知りたい人**
- **詳細設計の経験はあるが、上位設計（要件定義・画面設計など）をやったことがない人**
- **BoltなどのAI自動プログラム生成サービスを使う前に、設計力を確認したい人**
- **AIとの対話力（コンテキストエンジニアリング）を客観的に把握したい人**

> 💡 「仕様書を作る過程そのものが診断になる」設計です。特別な操作は不要で、Claudeと普通に対話するだけでスコアが算出されます。

---

## 3. 診断の仕組み

### 7軸のスキル評価

| 軸 | 内容 | 対応フェーズ |
|----|------|------------|
| 要件定義・スコープ管理 | 課題・ユーザー・スコープの整理力 | F1 |
| UX・画面設計 | 画面構成・操作フロー・デザイン方針 | F2 |
| セキュリティ設計 | 認証・データ保護・公開範囲の検討 | F1〜F3 |
| アーキテクチャ・技術選定 | 技術スタック・デプロイ・コスト設計 | F1・F3 |
| データ設計 | テーブル設計・バリデーション・入出力 | F4 |
| テスト設計 | テスト方針・自動/手動の使い分け | F6 |
| AIコラボレーション深度 | AIとの対話の質・主体性・判断力 | 全フェーズ |

### スコアの見方

- **自分から言及した項目**ほど高得点
- **具体的に答えた項目**ほど高得点
- **AIに聞かれてから答えた項目**は減点
- **未実施フェーズは0点扱いにならない**（実施したフェーズのみで評価）

## 4. 起動の仕方

このSkillは**明示的に呼び出して使います**。チャットの最初に以下のように入力してください。

### 設計支援として使う（診断なし）

```
webapp-design-diagnostic を使って仕様書を作りたい
```

起動時に「診断モードをオンにしますか？」と確認されます。不要な場合はオフを選べば通常の設計支援として使えます。

### 診断付きで使う

```
webapp-design-diagnostic を使って設計しながら診断もしたい
```

### 任意のタイミングで診断する

対話の途中でいつでも：

```
診断して
採点して
スコアを見たい
```

と言うと、その時点までの対話内容をもとにレーダーチャートと診断コメントが表示されます。

## 5. 複数日で作業する時のコツ

### 同じチャットで続ける場合（推奨）
→ そのまま作業を再開できます。対話履歴がそのまま残るため、診断データも継続して蓄積されます。

### チャットを変える場合
→ **前のチャットで以下のように依頼してから**、新しいチャットに渡してください。

```
引き継ぎまとめを作って。診断の経過もメモリに記録して。
```

引き継ぎの流れ：
1. 上記フレーズで引き継ぎドキュメント作成＋メモリ記録を依頼する
2. 出力されたドキュメントをコピーまたはダウンロード
3. 新しいチャットで `webapp-design-diagnostic を使って` と一緒に渡す

### メモリ記録について
- 診断後に「診断結果をメモリに記録しますか？」と確認される場合があります
- メモリ機能の設定によっては保存できない場合があります
- メモリに記録されている場合とそうでない場合では、次回セッションでの診断の精度が変わります

> ⚠️ 診断はチャット内の対話履歴をもとにスコアを算出します。チャットをまたぐと診断データはリセットされるため、できるだけ同じチャットで続けることを推奨します。

## 7. Claudeを使った開発の中での使い方

このSkillは「設計しながら設計力を鸽える」ことを目的としています。
Claudeを使ったWebアプリ開発の全体フローの中での位置づけはこうなります。

### Claudeを使った開発の全体フロー

```
① 【claude.ai（チャット）】設計（このSkill）
    claude.aiとの対話を通じて設計しながら自分のスキルを診断・向上させる。
    設計が完了したらCLAUDE.mdを作成する。
    ↓
② Claude CodeにCLAUDE.mdと設計書を渡す
    CLAUDE.mdがあることでClaude Codeがプロジェクトの
    文脈を理解した状態で作業を始められる。
    ↓
③ 【Claude Code & claude.ai】実装・デバッグ
    「何を作るか」は設計書が決め、「どう作るか」を
    Claude Codeと一緒に進める。
    実装中の相談はclaude.aiのチャットで行い、
    コードの生成・修正・デバッグはClaude Codeが担当する。
    バグが出たら再現手順と期待値をセットで渡すことで、
    Claude Codeが的確に修正できる。
```

> 💡 設計書の質が高いほどClaude Codeへの指示が明確になり、
> 手戰りが減ります。診断スコアを上げることは、
> そのまま実装フェーズの品質向上につながります。

### このSkillでは対応していないこと

| 対象外 | 代替手段 |
|--------|--------|
| 複数人の対話を合算した診断 | 各自が個別に診断して比較する |
| フェーズをまたいだリアルタイムの仕様書表示 | フェーズ完了時にmdファイルで出力 |
| CLAUDE.md の作成 | 設計書完成後、通常のチャットで作成できます |
| 実際のコーディング・実装 | Claude Code を使う |
| iOSアプリ・Androidアプリの設計 | 通常のチャットで相談 |
| 静的サイト（ブログ・企業サイトなど） | 通常のチャットで相談 |

> 💡 複数人で設計書を作っている場合、診断は「自分がチャットで説明できた内容」のみが対象になります。これは制約ではなく「自分が理解して言語化できたか」を測る診断として意図的な仕様です。
